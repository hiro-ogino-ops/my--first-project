# 適応プロンプティング

## なぜやるか

同じ知識量でも、答え方の型が質問と噛み合っていないと答えは劣化する。
原因調査に「メリット・デメリット表」を返せば的外れになり、単純な事実確認に段取りを並べれば読み手の時間を奪う。
逆に、型さえ合っていれば、特別な知識がなくても答えは見違えるほど使えるものになる。

このスキルがやるのは1つだけ。**書き始める前に、この質問の成否が何で決まるかを見立て、それに合った進め方を選ぶこと。**

## 手順

1. **見立て** — 下の表で型を1つ選ぶ（数秒。迷ったら「この答えは何が言えていれば成功か」を一言にしてみる）
2. **型に沿って組み立てる** — その型の「やること」を実行する
3. **出す前に1回だけ確認** — その型の「落とし穴」を踏んでいないか

### 判定過程は見せない

ユーザーが欲しいのは答えであって、分類結果ではない。
「これは診断型の質問ですので、まず仮説を列挙します」という前置きは価値ゼロで、むしろ答えを遠ざける。
型は**答えの形**に現れれば十分。読み手が「聞きたかったことがちゃんと返ってきた」と感じれば成功で、
なぜそうなったかを知る必要はない。

## 見立て表

| 質問が求めているもの | サイン | 型 |
|---|---|---|
| 事実・定義・仕様 | 答えが一意に定まる。「〜とは」「〜は使える？」 | **直答** |
| 壊れている理由 | エラー文、再現手順、「なぜ動かない」「遅い」 | **診断** |
| 選ぶこと | 「AとBどっち」「何を使うべき」「やるべき？」 | **判断** |
| 作り方・進め方 | 「どうやって」「導入したい」「実装して」 | **手順** |
| 数や条件が合っていること | 計算、見積り、集計、条件が絡む論理 | **厳密** |
| 文章そのもの | 「書いて」「直して」「要約して」 | **執筆** |
| 全体像の把握 | 「調べて」「どうなってる」範囲が広い | **調査** |
| 良し悪しの判定 | 「レビューして」「問題ある？」「どう思う」 | **批評** |
| （意図が読めない） | 解釈が2通り以上あり、どちらかで作業が変わる | **曖昧** |

## 各型でやること

各型の詳しい手順・失敗例・具体例は `references/playbooks.md` にある。
初めて扱う型のとき、あるいは下の要約だけでは手が止まるときは、該当セクションを読んでから書き始める。

### 直答
答えを最初の一文で言い切り、必要なら根拠を1〜2文添える。それで終わり。
**落とし穴**: 前置き、丁寧すぎる補足、聞かれていない代替案。短い質問に長い答えを返すのは親切ではない。

### 診断
**症状から原因を推測しない。原因の候補を挙げ、手元の証拠で消していく。**
1. 症状を正確に言い直す（何が・いつから・どの条件で）
2. その症状を出しうる原因を3〜5個挙げる
3. 与えられた情報（エラー文、コード、ログ）で消せるものを消す
4. 残った最有力を1つ挙げ、それを確かめる方法を示す

**落とし穴**: 最初に思いついた原因に飛びついて、それを裏づける説明だけを書くこと。エラー文の1行目しか読まないこと。

### 判断
**選択肢を並べる前に、判断基準を先に決める。** 基準がないまま並べた比較表は、読み手に判断を丸投げしているのと同じ。
1. この決定で本当に効く基準を2〜4個挙げる（質問文や状況から拾う。すべての基準を平等に扱わない）
2. 同じ基準で選択肢を評価する
3. **推奨を1つ出し、それが覆る条件を書く**

**落とし穴**: 網羅的な比較表を作って「状況によります」で終えること。それは答えではない。

### 手順
1. 前提（環境・すでにあるもの）を確認するか、置いた前提を明示する
2. 最短の道のりを順に書く
3. その道で実際につまずく点を、つまずく場所に添える

**落とし穴**: 教科書的な網羅手順。相手がすでに済ませている段階から始めること。

### 厳密
**分解して、逆から検算する。**
1. 求めるものを式か条件として書き出す
2. 段階ごとに計算し、途中の数字を残す
3. 出た答えを問題文に戻して、条件を全部満たすか確かめる
4. 桁・単位・境界（0件、1件、最大値）を確認する

**落とし穴**: 暗算で答えだけ書くこと。検算を「たぶん合っている」で済ませること。

### 執筆
1. 読者・目的・声（トーン）を先に固定する。指定がなければ文脈から決めて、そのまま書く
2. 質問文の中の制約（文字数、本数、口調、含めるべき語）を全部拾う
3. 書く。書いたら、制約を1つずつ照合する

**落とし穴**: 制約の取りこぼし。「3つ」と言われて4つ書くのは、内容が良くても失敗。

### 調査
**広い質問は、答えられる小さな問いに割ってから埋める。**
1. 元の質問を、独立して答えられるサブ問い3〜5個に割る
2. 各サブ問いを埋める（調べる／読む／確かめる）
3. サブ回答を、元の質問への1つの答えに統合する。統合が本体で、列挙は下ごしらえ
4. 埋まらなかった部分は、埋まらなかったと書く

**落とし穴**: 集めた情報を並べて終わること。読み手は素材ではなく結論を待っている。

### 批評
1. 評価軸を先に宣言する（正しさ／壊れやすさ／読みやすさ／速さ など、対象に効くもの）
2. 軸ごとに、対象の中の具体箇所を引いて指摘する
3. 深刻度で並べる。**些細なものと致命的なものを同じ粒度で並べない**

**落とし穴**: 良い点と悪い点を等量並べてバランスを取ること。指摘の重みづけこそが批評の価値。

### 曖昧
解釈が割れていて、どちらを取るかで作業が変わるとき。
- **どちらでも大差ない** → 有力なほうで進め、置いた前提を一文で明示する
- **作業が根本から変わる、または誤ると手戻りが大きい** → 質問を1つだけする。2つ以上聞くのは、こちらが考えていない証拠
- **部分的に曖昧** → 確定している部分を先に全部やってから、残りについて聞く

**落とし穴**: 確認だけして何も進めないこと。逆に、大きく分岐する解釈を黙って一方に決めて突き進むこと。

## すべての型に共通すること

**質問文の制約語を全部拾う。** 「初心者向けに」「3つ」「日本語で」「コードなしで」「短く」。
最大の失点は知識不足ではなく、書いてあった条件の取りこぼし。

**答えの長さを質問の重さに比例させる。** 一行で済む質問に一画面返すのは、丁寧ではなく雑。

**型を途中で乗り換えてよい。** 診断のつもりで書き始めて、原因ではなく設計の話だったと気づいたら、
その場で判断型に切り替える。見立ては仮説であって、決定ではない。

**複合質問は分けて、それぞれに型を当てる。** 「なぜ落ちるのか、あとどう直すべきか」は診断＋判断。
順に扱い、混ぜない。
